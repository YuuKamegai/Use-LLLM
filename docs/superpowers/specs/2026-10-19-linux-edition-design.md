# Use-LLLM Linux 版 設計

作成日: 2026-10-19（日本時間）
状態: 本文はユーザーレビューで承認済み。製品コードの実装は未着手。
配置の追記: ユーザー指定により Linux 側の ~/Use-LLLM-Linux をアプリ配置先とする。

## 1. 目的と合意した条件

研究室・共同研究者へ配布し、利用者が専用仮想環境を手動で有効化せずに
アプリ一覧から起動できる Linux 版を作る。Windows 版と本体コードを共用する。

- Ubuntu 系を対象とし、初版の検証基準を Ubuntu 24.04 LTS・x86_64・GNOME デスクトップとする。
- Ollama と Azure OpenAI の両方を初版で利用可能にする。
- インターネット接続を初回セットアップ・更新時に利用できる。
- 配布先で専用 Python 仮想環境を作成し、依存関係を固定する。
- ブラウザー UI、MCP 接続、履歴、成果物、HTML 書き出し、日英表示、Web 検索を共用する。
- 通常起動は一般ユーザー権限。OS パッケージが不足する場合だけ追加導入を案内する。
- 起動の正常応答を確認してブラウザーを開く。既存プロセスがあれば再利用する。
- API キーは Secret Service を利用し、利用不能時に平文へフォールバックしない。

更新・障害対応・完了条件を含む本文は承認済み。配置先はその後の指定を反映する。

## 2. 対象外

- Linux サーバーを LAN／インターネットへ公開する運用、複数ユーザー向け認証。
- ARM、他ディストリビューション、KDE、ヘッドレス環境の動作保証。
- Ollama 本体・モデル・GPU ドライバーの自動導入。
- 外部 MCP サーバー本体の移植・同梱、Windows 専用ツールの互換化。
- Windows DPAPI で暗号化済みの API キーの Linux への自動移行。
- 初版での自動更新、パッケージリポジトリ、deb／AppImage／コンテナ配布。

Ubuntu の他バージョンでの動作は、検証するまで対応済みと表記しない。

## 3. 配布・導入

バージョン識別子付きの tar.gz にソース、静的アセット、pyproject.toml、uv.lock、
Linux 用セットアップ・起動・更新・削除スクリプト、README を含める。
開発用キャッシュ、Windows バイナリ、.venv、個人設定・履歴・API キーは含めない。

セットアップは次の順に行う。

1. OS、CPU、必要コマンド、書き込み権限、既存導入を検査する。
2. 利用可能な uv を確認する。未導入なら公式の導入方法を案内し、黙って root 権限を使わない。
3. リリースで指定した Python 3.12 系のパッチ版を uv で取得する。
4. 最終配置先のリリースディレクトリで .venv を作成し、uv.lock に従って実行用依存のみを導入する。
5. 一時データ領域を使って import、アセット、起動・ヘルスチェックを確認する。
6. 有効リリースへの参照と .desktop エントリーを作成する。

OS の Python を書き換えず、sudo pip は使用しない。仮想環境は配置後に生成し、
別パスで作った仮想環境のコピーや移動を配布方法としない。
初回導入時の依存取得に必要な接続先・プロキシ制約は手順に記載する。

## 4. 配置と OS 境界

標準の配置は以下とする。XDG 変数が設定されている場合は、その値を優先する。

| 種類 | 標準位置 |
|---|---|
| アプリ配置ルート | ~/Use-LLLM-Linux/ |
| アプリ・各リリースと専用 .venv | ~/Use-LLLM-Linux/releases/<release-id>/ |
| 有効リリースへの参照 | ~/Use-LLLM-Linux/current |
| 起動入口 | ~/.local/bin/use-lllm-webui |
| アプリ一覧の項目 | ~/.local/share/applications/use-lllm.desktop |
| 設定・初回設定 | ~/.config/use-lllm/ |
| 会話 DB・成果物 | ~/.local/share/use-lllm/data/ |
| ログ | ~/.local/state/use-lllm/logs/ |
| 起動管理情報 | $XDG_RUNTIME_DIR/use-lllm/ |

上記の ~/ は配布先 Linux ユーザーのホームであり、Windows 側のホームではない。
アプリ配置ルートは XDG 変数では変更せず、設定・データ・ログ・アプリ一覧の配置に XDG を適用する。
XDG_RUNTIME_DIR が利用できない場合は所有者専用の状態ディレクトリを使う。
USE_LLLM_DATA_DIR を明示した運用では、互換性のため既存どおりその配下に
DB・成果物・設定をまとめる。設定・データのファイルは 0600、専用ディレクトリは 0700 を基本とする。

OS 判定と配置計算は小さなモジュールへ集約する。
Windows の既存保存先、DPAPI 形式、起動方法は維持する。
セッション管理全体や UI の全面改修は行わない。

## 5. API キー保管

共通の保存・読出しインターフェースを設け、Windows は既存 DPAPI、
Linux は keyring 経由の Secret Service バックエンドを利用する。
Linux ではバックエンドを明示的に検査し、平文・代替ファイル保存のバックエンドを拒否する。

Linux の settings.json には秘密値ではなく、接続ごとの不変 ID に基づく参照を保存する。
接続名を変更しても参照が壊れないようにする。設定・API・ログへ秘密値を出さない。
キー置換は新しい参照へ保存してから設定を原子的に更新し、成功後に古い参照を削除する。
設定更新失敗時は新しい参照を回収する。接続削除時も関連する秘密を削除する。

Secret Service が停止・ロック中の場合も、WebUI と Ollama の利用を妨げない。
Azure 接続を利用不能として画面に理由と解除方法を表示し、キーを空値で上書きしない。
Azure 選択中でも、利用者が Ollama へ切り替えられる状態を保つ。

Windows の保護済み設定を持ち込んだ場合は、秘密を保持したまま互換性エラーを案内し、
Linux 上でのキー再入力を促す。自動的に復号・送信・再暗号化しない。
MCP の env／headers 等に任意入力された値の保管方式の全面変更は本移植の対象外とし、
既存仕様を維持する。ただし Linux の設定ファイルへのアクセス権は制限する。

## 6. 起動・二重起動・終了

ショートカットと CLI は同じ Linux 起動処理を使用する。
仮想環境の Python を絶対パスで呼び、カレントディレクトリに依存しない。
PATH、空白・日本語を含むパス、実行権限を考慮する。

起動ロックで同時起動を排他する。実行中プロセスの確認には PID だけを使わず、
所有者、プロセスの識別情報、対象リリース、起動ごとの識別子、ヘルス応答を照合する。
ヘルス応答の application と static_ready だけで別インスタンスを再利用しない。
識別子に秘密値や既存 CSRF トークンを流用しない。

稼働済みなら既存 URL を開く。既定ポート 8765 を他プロセスが使用している場合は、
起動可能なループバックポートを選び、USE_LLLM_WEB_PORT と OAuth callback へ同じ値を渡す。
選択から bind までの競合は限定回数の再試行で処理する。

サーバー起動後、一定の短い間隔でヘルスを確認し、最大 30 秒で打ち切る。
固定秒数だけ待ってブラウザーを開く方式は使わない。
ブラウザー起動だけが失敗した場合はサーバーを維持し、URL を表示する。
ブラウザーを閉じてもサーバーは継続し、起動コマンドの stop／status で管理できるようにする。
正常終了では MCP セッションと子プロセスを閉じる。停止対象は自分のインスタンスに限定する。

## 7. 更新と削除

初版はダウンロード済みのリリースアーカイブを明示して更新する。
出所を確認した配布物を使い、自己更新や起動ごとのネット取得は行わない。
配布時は SHA-256 一覧を生成するが、隣接したチェックサムだけを配布元の認証とは見なさない。

更新は既存の仮想環境を上書きせず、別の最終リリースパスへ新しい環境を作る。
検証が成功するまで current を切り替えない。失敗時は旧リリースを維持する。
アーカイブの展開では絶対パス、領域外への ../、危険なリンクを拒否する。

実行中の更新では、実行を勝手に中断せず、停止が必要なことを案内して適用を中止する。
停止後、更新前に設定・DB を退避する。DB の退避は SQLite の一貫したバックアップを使う。
保護されたバックアップもアクセス権を制限する。Secret Service の秘密はバックアップへ書き出さない。
初版では DB スキーマ変更を伴わない移植とし、バイナリの切戻しだけで DB を戻せるとは仮定しない。

削除はアプリ、ショートカット、起動入口を対象とし、会話・設定・キーは既定で残す。
データとキーの削除は独立した明示オプションにする。
共有の uv・Python キャッシュや Ollama・外部 MCP サーバーは削除しない。

## 8. エラー表示とセキュリティ

導入失敗、依存不足、キー保管サービス不調、起動タイムアウト、設定不正、MCP 接続失敗を
区別し、利用者が次に行う操作とログの保存先を表示する。
CLI では非ゼロ終了コードを返し、デスクトップ起動では利用可能な通知機能で案内する。
通知機能が使えない環境でもログと端末起動による診断手段を残す。
ログはサイズ・世代を制限し、秘密や会話本文を診断のために追加記録しない。

既存の loopback bind、Host 制限、same-origin 検証、起動ごとの CSRF トークン、
MCP の承認とネットワーク許可、Web 検索の明示的な有効化を維持する。

## 9. 完了条件と検証

### 自動検証

- Linux／Windows の保存先計算、環境変数による上書き。
- DPAPI の既存設定の互換性、Linux キー保存・更新・削除、保管不能時の動作。
- 既存 Python／JavaScript テストの実行。ブラウザーテストの Python パスとブラウザー指定を OS に対応。
- インストール・更新・失敗時の旧版維持・削除・設定保持。
- 二重起動、無関係なポート占有、古い PID 情報、起動失敗、ヘルス待機。
- 配布アーカイブに必要なアセットが含まれ、秘密・履歴・開発キャッシュが含まれないこと。

### Ubuntu デスクトップ上での受入検証

- クリーンな Ubuntu 24.04 LTS・x86_64 で、文書どおりに展開・セットアップできる。
- アプリ一覧から実際に起動し、/general/ と静的アセットが表示される。
- 再起動・二重起動・停止、占有ポートへの対応を確認する。
- Ollama での実会話と Azure での保存・再起動後の接続を確認する。
- Secret Service のロック・停止で、秘密を漏らさず Ollama が使える。
- Linux 対応のテスト MCP サーバーで stdio／HTTP、承認、終了・再接続を確認する。
- 提供された実 MCP サーバーがある場合はその接続も確認し、未提供なら未検証として記載する。
- 履歴、成果物、HTML 書き出し、日英表示、Web 検索の利用を確認する。
- 更新後も会話・設定を維持し、削除の既定動作でデータが消えない。

Linux の実行環境・デスクトップ・実 Azure 接続情報がない場合は、利用できる範囲の検証を進め、
未実施の項目を明記する。WSL／コンテナだけでデスクトップの受入検証完了とはしない。
Windows でも従来の起動と DPAPI 設定を確認する。
